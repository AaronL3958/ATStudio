ATStudio browser chord recognition

Original model: MusicX, ISMIR2019-Large-Vocabulary-Chord-Recognition
Pinned source: https://github.com/music-x-lab/ISMIR2019-Large-Vocabulary-Chord-Recognition/tree/481f4ce703f8822b99f4037e9104ba1760e21ea3
License: MIT (included). CQT kernels derive from librosa 1.0.0 (ISC license included).

All five supplied, non-reweighted pretrained folds were exported to ONNX.
The maximum absolute logit difference against PyTorch was below 0.00006 on
240-frame random fixtures, with dynamic sequence lengths.

Browser adaptations:
- 22,050 Hz mono audio and centered 512-sample CQT hops (23.2 ms).
- Multirate complex CQT with centered FIR decimation and a pseudo-CQT high end.
- A held-chord fixture matched librosa hybrid_cqt with cosine similarity 0.99999.
- Fixed concert-pitch tuning; upstream automatic tuning is not reproduced.
- 768-frame inference blocks with 128-frame overlap/context on either side.
  Instance normalization and bidirectional context are block-local, unlike
  upstream whole-track inference. Predictions are not guaranteed identical.
- Fast mode uses fold 0. Thorough mode averages probabilities from all five.
- Stable Viterbi decoding, minimum chord duration, supported guitar vocabulary,
  seventh-head optional, and bass marginalization for chord inversions.
- No silent fallback to template-only chords if neural inference fails.

Scope: This is a chord recognizer, not vocal source separation or piano
transcription. Piano uses Basic Pitch candidates and two monophonic voice paths
for a simplified melody-and-bass draft. Dense mixes, quiet vocals, rubato, and
competing lead instruments need review. Key estimates include alternatives.
No accuracy guarantee has been established on the user's Aerosmith recording.

Runtime: models load only for analysis in a disposable, single-threaded WASM
worker. Leaving Learn cancels it. The app does not upload audio to an external
inference service. Account song storage uses the site's existing D1 and R2.

Reproduce model exports (not required for normal site builds):
1. Install scripts/model-export-requirements.txt in a Python environment.
2. Check out the upstream repository at the pinned commit above.
3. Run python scripts/export-musicx.py /path/to/upstream from the site root.
4. Run node scripts/build-learning-worker.mjs; npm run build does this too.
